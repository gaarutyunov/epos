Package agent skills the way you already package everything else, and build new ones out of the ones you trust.

Install

go install github.com/gaarutyunov/epos/cmd/epos@latest

Quick start Reference

What it is for

  • Pin the skill your agent runs, the way you pin a container image.
  • Derive a house skill from several published ones, and rebuild it when they move.
  • Ship one artifact and let each project decide which parts of it apply.

Features

An artifact, not an attachment

A skill directory becomes a standard OCI artifact — content-addressed, tagged, and pullable by oras or any other conforming client. No new server, no new account, no daemon.

epos pack

Compose instead of forking

Start from a skill someone else publishes, remove the parts that do not apply, rewrite the parts that nearly do, and keep the rest. A fork you have to re-merge becomes a recipe you re-run.

epos build

Several bases, one skill

Named stages, each from its own source, and cross-stage copies between them. Five published skills can become one that reads as though it was written that way.

FROM … AS · COPY --from

Parameters, resolved at install

The artifact ships its templates untouched; your values fill them in on the machine that installs it. Turn a dependency off for one project and back on for the next without rebuilding.

epos install -f values.yaml

Pinned, and reproducible

Every worktree records the digest it installed, and the same recipe over the same bases always produces the same bytes. A build is a pure function; nothing executes.

skills.lock.json

Signed and verifiable

Sign a published skill and attest what it was built from, as OCI referrers, then verify before you install. The provenance travels with the artifact rather than beside it.

epos sign · attest · verify
